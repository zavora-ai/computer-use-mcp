# What users love about computer-use and browser-agent products (as of 2026-10-25)

## Which concrete features get praised, and by whom? (ranked by how often and how strongly)

### Takeaway
The most praised features have little to do with raw autonomy. People praise an agent that works in their own signed-in session, that they can watch and take over at a login, 2FA or checkout, and that, from April 2026, runs in the background without taking their cursor. Developers add their own requirement: precise, token-cheap control through the accessibility tree or element refs instead of pixels. Scheduled tasks, record-and-replay, memory and voice get heavy vendor investment but much thinner genuine user praise. Speed is the most common complaint about every hosted agent.

### Evidence labels used below
- **[User]**: a named or pseudonymous end user (HN comment, X post, a long-term personal review).
- **[Press]**: a journalist's or blogger's hands-on opinion. Several 2026 "review" sites are affiliate or SEO pages; they are flagged where relevant.
- **[Vendor]**: the company's own claims or docs.
- **[Metric]**: stars, downloads or usage counts. GitHub, npm and PyPI figures were pulled from their public APIs on 2026-10-25.

### Ranked summary (my ranking: count of independent sources weighted by evidence quality; detail and citations follow)
| # | Feature (what exactly it does) | Evidence strength | Who praises it |
|---|---|---|---|
| 1 | Acts inside the person's own signed-in browser or apps, so cookies, logins and sessions carry over | Strong: user, press and metric | Consumers and developers |
| 2 | Watch it live, pause, take over, hand back (login, 2FA, CAPTCHA, a decision) | Strong: user, press, vendor | Consumers |
| 3 | Stops at the irreversible step (checkout, Send) without over-confirming | Medium: praised when right, attacked when excessive | Consumers, developers |
| 4 | Runs in the background without stealing cursor or focus; parallel virtual cursors | Strong and rising since Apr 2026 (press, user, metric) | Mac power users, developers |
| 5 | Multi-tab and multi-page research synthesis (@tab, chat with tabs, wide research) | Strong: user and press | Consumers, knowledge workers |
| 6 | Precise structured targeting: accessibility tree / element refs instead of screenshots | Strong among developers (press, user, metric) | Developers |
| 7 | Token and context efficiency, speed | Strong among developers; speed is the top hosted complaint | Developers, everyone |
| 8 | Isolation: VM, sandbox or separate agent desktop | Medium-strong among developers | Developers, IT |
| 9 | Remote dispatch from a phone or chat app to an agent on your own machine | Strong adoption metric, little written praise | Power users |
| 10 | Voice plus a screen-aware helper that points at UI (tutor mode) | Medium: one viral open-source hit, mixed for voice elsewhere | Learners, creative-app users |
| 11 | MCP integration with existing assistants | Strong metric for browser MCPs; contested on token cost | Developers |
| 12 | Scheduled / recurring tasks, saved shortcuts, record-a-workflow | Heavy vendor push, thin user praise | Vendors, some reviewers |

### Cited Findings

### Inferences
- The two loved features with the strongest evidence, "my own session" and "I can take it back", are both about trust and continuity, not intelligence. Products that run in a cloud browser (ChatGPT agent's virtual browser) lose on the first; products that cannot be corrected mid-run (Opera Neon Do) lose on the second.
- Background, no-cursor operation became a headline feature in April 2026 (Codex, cua-driver) and is now a comparison point for any desktop agent. computer-use-mcp's `delivery: "pid"`, `set_target`, and capture of covered windows are on the right axis. The praised implementations add visible parallel virtual cursors and the AX tree as the primary channel.
- Among developers, the axis that drives switching is tokens per step and steps per task (agent-browser, Playwright CLI and skills over Playwright MCP, PinchTab). A desktop MCP server is judged on context cost per observation as much as on capability; computer-use-mcp's 11k-token `desktop` profile and `run_steps` speak to this.
- The status card's Pause and Stop, a visible log of actions and the "taken over" pause in computer-use-mcp match what users praise in hosted agents (watch, pause, take over). What hosted products add is an explicit hand-back: the agent resumes the same task once the person clears a 2FA or login.
- Scheduling, recording and memory are where vendors invest, but end users do not yet praise them in their own words. Treat them as possible later wins, not proven reasons people adopt a product.
- Phone or chat dispatch to an agent on one's own machine (OpenClaw, Hermes, Claude Dispatch) has the largest adoption signal found. A desktop MCP server can't supply this; it falls to the host, but the server has to survive unattended runs (locked screen, sleep).

- I found no user-generated evidence that praises OCR, benchmarks or observability dashboards as a reason to adopt.

## Which features do power users and developers praise in open-source tools?

### Takeaway
Developers reward open-source tools for four things: control of their real, logged-in browser or desktop; low token cost per step (refs and CLIs over full-tree MCP dumps); deterministic, cacheable steps with LLM fallback; and isolation (VMs, containers) when the agent isn't trusted.
