# v7.7.0: honest results, a person in control, faster captures

From [the 2026-10-23 competitor study](https://github.com/zavora-ai/computer-use-mcp/blob/v7.7.0/docs/reviews/2026-10-23-competitor-study.md):
its 7.6.2 list of confirmed defects (7.6.2 was never released) and its 7.7 list of the contracts other desktop agents
converged on in October. The task record is
[`docs/specs/v7.7/tasks.md`](https://github.com/zavora-ai/computer-use-mcp/blob/v7.7.0/docs/specs/v7.7/tasks.md).

## Every action says what happened

Each action reply carries `effect`, `route` and, for input, `delivery`:

| `effect` | Meaning |
|---|---|
| `verified` | The result was read back and matches: an activation confirmed by the frontmost app, a `set_value` or clipboard write read back. |
| `changed` | The target looked different after the action; the intended state was not read back. |
| `no_visible_change` | It looked the same before and after: the action probably did nothing. |
| `unverified` | The input was posted and nothing confirms it landed. |

Every refusal and every unverified result also carries a `hint` and a `next_call`. The `next_call` is always a
read-only tool this session can call, so an agent can run it as is. Pass `verify: true` to an input tool to capture
before and after.

## `run_steps`

A known sequence in one call: click a field, type, press Return. Every step is validated before any runs, the target
is focused once, the batch stops at the first failing step, and one capture can follow the last step. It is in the
default `desktop` profile.

## A person stays in control, by default

- **The status card is on by default on macOS and Windows** (Linux: `COMPUTER_USE_STATUS_CARD=true`). It shows what
  the agent is doing, with Pause and Stop. Stop now lands in milliseconds: the card's control file is watched, and slow
  native calls no longer hold the server's event loop. On Windows the card counts as shown only once its window has
  rendered; where it cannot appear (a service or session-0 desktop), `doctor` says why.
- **`ctrl+alt+escape` stops the agent** on macOS and Windows. `COMPUTER_USE_EMERGENCY_CHORD` changes it, and `off`
  disarms it.
- **Taking over pauses the agent.** When the person moves the mouse deliberately, clicks or types during an action, the
  agent stops with `taken_over` and resumes 5 s after they stop. The card says "You took over".
  `COMPUTER_USE_TAKEOVER=false` turns this off.
- **A locked screen is refused by name** (`screen_locked`), and so are a disconnected Remote Desktop session and the
  Windows secure desktop. The display stays awake while the agent works.
- **After Stop, the card can be closed.** The Stop button reads Close; the card goes away and the agent stays stopped
  until the server restarts.

## Faster, exact captures

- **macOS:** full-screen captures go through ScreenCaptureKit in a helper that stays running. In the measured runs a
  warm capture took 62 ms and a `screenshot` 112–128 ms end to end. Before, `screencapture` and `sips` took
  157–223 ms. `display_id` picks a display. The pointer overlay and the status card never appear in a capture.
- **Windows:** the process is per-monitor DPI aware, so a coordinate from a screenshot, a window's bounds or UI
  Automation is the same pixel the click lands on, at any scale and on any monitor. A window capture tries
  `PrintWindow`, then Windows.Graphics.Capture, then a screen crop marked as covered, and names the method and the exact
  rectangle.
- **Linux:** windows have real geometry, sway and Hyprland are supported, and the desktop portal captures on Wayland.
  A missing tool is an error that names the package.
- An unchanged capture comes back as a short text, not the same image, up to three times in a row.

## Fixed

- A stopped or cancelled drag, click or `hold_key` releases every button and key it pressed, on every platform.
- On Windows, input blocked by a higher-integrity window is an error, not success. Absolute input is normalised over
  the whole virtual desktop, and PowerShell output is UTF-8.
- **Windows tools, from a live check of every tool on a Windows 11 desktop:** `left_mouse_down` / `left_mouse_up` press
  at their coordinate (they pressed wherever the cursor was); `notification` works with PowerShell 7 installed;
  `registry set` creates a missing key, and its errors are one plain line; `get_active_space` returns the desktop's GUID
  instead of failing its output schema; and `find_element` finds every role `get_ui_tree` reports (panes as `AXGroup`,
  tab items as `AXRadioButton`), while a misspelt role is refused with the closest valid ones instead of matching
  everything.
- `process_kill {mode: "list"}` on Windows no longer starts PowerShell. A filesystem search or a process list no
  longer waits on another server's desktop lock.
- `scrape` fetches public addresses only, with each redirect checked.
- Long text is typed, not pasted, when the clipboard holds an image or files, so they are not lost.
- Release staging tolerates an already-staged version and skips natives after a release. Builds run without `npx.cmd`.

The full list is in the [CHANGELOG](https://github.com/zavora-ai/computer-use-mcp/blob/v7.7.0/CHANGELOG.md).

## Upgrading

- **Results gain fields.** `effect`, `route`, `delivery`, `hint` and `next_call` are added to each action's result. A
  JSON reply gains them as fields; a text reply keeps its text first and gains a JSON block. Both appear in
  `structuredContent`. Nothing is removed.
- **The default list is 37 tools on macOS** (33 on Windows and Linux). The five click aliases are listed only in
  `full`, but a host that calls `left_click` keeps working in every profile. `run_steps` is new.
- **On macOS and Windows the card appears on the first desktop action.** Set `COMPUTER_USE_STATUS_CARD=false` for a
  headless host.
  A host that drives the mouse itself while the agent works should set `COMPUTER_USE_TAKEOVER=false`, or the agent will
  pause.
- **`scrape` refuses private and local addresses.** Name the hosts in `COMPUTER_USE_SCRAPE_ALLOWED_HOSTS`, or set
  `COMPUTER_USE_SCRAPE_ALLOW_PRIVATE=true`.
- **Windows coordinates are physical pixels.** At a scale above 100 % they used to be virtualised to 96 DPI. Agents that
  take coordinates from a screenshot or `get_ui_tree` need no change. A host that computed its own logical coordinates
  can set `COMPUTER_USE_WINDOWS_DPI_AWARENESS=unaware`.

## Known limits

- Every Windows tool was run on a Windows 11 desktop (one 1920×1080 display at 100 %): 89 checks passed. It was not
  tried on a two-monitor desktop at 150 %, which is the setup the study asks for. On Windows, `select_menu_item` is
  not implemented and `open_application` cannot start an app that is not running.
- The macOS 27 name "Device Control and Data Access" comes from Peekaboo 4.9.4. It was not seen on a macOS 27 machine,
  so the remediation gives both names.
- GNOME on Wayland lists only XWayland windows to other programs, and Linux input on Wayland is still `ydotool`. The
  plan is in [`docs/specs/v7.7/wayland.md`](https://github.com/zavora-ai/computer-use-mcp/blob/v7.7.0/docs/specs/v7.7/wayland.md).
