# v7.5.0 — agent desktop: work beside the user, read what draws itself

> Status: built 2026-10-01 and shipped inside [v7.6.0](v7.6.0.md) on 2026-10-09. There is no separate 7.5.0 package or tag.

Found while building a racing game with Unreal and Blender: the agent stopped using this
server. Input was posted at the HID tap, so it went to whatever app James had in front and
moved his real cursor while he worked. Unreal and Blender draw their own UI, so the
accessibility tree was empty and only pixel guesses were left. `screenshot {target_app}`
returned an Unreal notification toast instead of the editor, which made a harmless toast
look like a blocking modal. And there was no way to press the key that opens a game's
console. This release fixes those four things.

## Don't take over while the user works

A call that would activate an app or post keyboard or mouse input within
`COMPUTER_USE_USER_IDLE_MS` (default 4 s) of the user's last physical input is refused:

```json
{"status": "user_active", "msSinceInput": 73, "wouldDo": "left click at (400, 300) in com.apple.TextEdit",
 "hint": "... Wait at least 3927 ms and retry, deliver the input to the target app without focus (delivery: \"pid\", macOS), or pass force: true if the user asked for this action."}
```

Reads (captures, OCR, window lists, accessibility reads) are never blocked. The clock is the
existing passive HID monitor, which ignores this server's own events; without Input
Monitoring permission it cannot tell, so the guard allows the call and `doctor` says so.

## Input to a background app

`delivery: "pid"` posts events to the target process with `CGEventPostToPid`: nothing is
activated and the cursor does not move. Apps decide what they accept, so the server watches:
the first pid delivery of each kind (keyboard, pointer) to an app is checked by capturing the
window before and after, and the outcome is recorded. `delivery: "auto"` (the default) uses
pid delivery while the user is active, but only for an app and input kind seen to work.

Measured on a background, covered TextEdit window: typing, the grave key and `type mode:"keys"`
arrived exactly; menu shortcuts (`cmd+p`) and clicks into the text view did nothing. The Unreal
Editor and Blender results are pending a run by the editor owner (steps in the
[design](../specs/v7.5-agent-desktop/design.md), §6).

## Read apps that draw their own UI

```typescript
await client.callTool('read_window_text', { target_app: 'com.epicgames.UnrealEditor', region: [0, 0, 600, 40] })
// {"lines": [{"text": "File", "box": {...window points}, "screen": {...screen points}}, ...]}
await client.callTool('click_text', { text: 'Build', target_app: 'com.epicgames.UnrealEditor' })
```

`read_window_text` OCRs a window on device with Apple Vision, covered or not, without
activating it: the whole Unreal editor window in about half a second. A region costs a few
dozen tokens; a whole editor window about 2.5 k. `click_text` clicks text by what it says.
`wait_for_window` replaces sleep-and-screenshot loops while a dialog opens or an app loads.

## The window the agent means

`list_windows` labels each window `main`, `document`, `dialog`, `panel`, `toast` or `other`.
`screenshot`, `zoom` and `snapshot` with `target_app` take the main window, the largest titled
one, and `target_title` picks another. On macOS 14+ a window capture goes through
ScreenCaptureKit: the window alone, even when covered, without its shadow, so the reply states
an exact image-to-screen mapping instead of an approximate one.

## Real key events

`key` knows `grave`, `backtick`, `tilde` and the punctuation by name, and an unknown name now
comes back with the list of valid ones. `type` with `mode: "keys"` sends each character as the
key-down/up of its virtual key, read from the current keyboard layout, so key bindings such as
Unreal's console receive it.

## Requirements and rollout

- The OCR and capture helper is Swift, compiled on first use into
  `~/Library/Caches/computer-use-mcp/` (about 3–5 s once). It needs Xcode or the Command Line
  Tools (`xcode-select --install`); `doctor` reports `agent_helper`. ScreenCaptureKit capture
  needs macOS 14. Older systems keep `screencapture`.
- The guard needs Input Monitoring for the agent host (System Settings > Privacy & Security).
  Set `COMPUTER_USE_USER_IDLE_MS=0` to turn it off.
- 73 tools (`read_window_text`, `click_text`, `wait_for_window` added). Existing tool names,
  arguments and results are unchanged; every addition is optional. `user_active` refusals are
  new behaviour for callers that send input while the user types: retry after the wait,
  use `delivery: "pid"`, or pass `force: true`.
- Windows and Linux: window kinds, key names, `type mode:"keys"` (US-ANSI) and `wait_for_window`
  work; the OCR tools and pid delivery report `platform_unsupported`; the user-active guard is off
  unless `COMPUTER_USE_USER_IDLE_MS` is set.
