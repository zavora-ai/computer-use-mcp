# Computer Use MCP 7.2.0

Release date: 2026-09-10

This release adds application discovery, a run console a person can watch an agent
work in, pointer gestures for applications that expose no controls, optional
services for agent hosts, and runnable Responses API showcases. It also makes the
repository easier to navigate and separates implemented features from platform
prerequisites and validation.

## Changes

- Discover installed and running applications with `discover_applications`,
  including Office queries and bounded capability checks. The full profile now
  exposes 66 tools; the original 64 tool names and schemas are retained.
- Add an agent run console: five tools (`run_start`, `run_plan`, `run_progress`,
  `run_say`, `run_console`) and an MCP App at `ui://computer-use/run-console/v1`,
  behind `runConsole: true`, taking the surface to 71 when enabled. An agent
  declares a plan, marks one task active at a time and attaches real captures as it
  works, so a person follows the work instead of a tool log. The transcript is also
  the steering channel: every run tool reply returns it, so a message typed
  mid-task reaches the agent on its next call. `computer-use-mcp-console` serves the
  UI, the MCP Apps bridge and an `/mcp` endpoint from one process so a browser and
  an agent read the same run; it is loopback-only and unauthenticated by design.
- Add `mouse_drag` for applications that draw their own interface and expose no
  accessible controls. A chosen button plus modifiers held across interpolated
  waypoints is what a 3D viewport orbit, pan or canvas stroke actually requires;
  a single-button jump to an endpoint is ignored by applications that integrate
  incremental motion.
- Add owner-bound desktop sessions, observation-based actions, verified workflows,
  persistent Tasks, a portable MCP App console and stronger authorization checks.
- Add isolated browser contexts, Docker-backed JavaScript execution, Linux worker
  setup and native takeover supervision as optional host integrations.
- Add lazy tool discovery, compact observations, local waits, image reuse,
  usage accounting and bounded tool text for agent loops.
- Add Responses API paint, Office and inspection recipes. Paint batching preserves
  real pointer strokes and verifies export. Office instructions select macOS
  AppleScript or Windows PowerShell/COM. Save probing is optional.
- Preserve screenshot targets and type-clearing options in the OpenAI adapter.
- Replace the README with practical setup, usage, an architecture diagram and the
  actual agent-painted showcase. Remove obsolete debug probes and legacy demos.

## Compatibility and prerequisites

Node.js 20+ and the same six native targets are retained. Legacy MCP clients still
work; modern protocol features and additional host services remain opt-in.
The Rust crate's internal version is independent of the npm release version.

Desktop permissions and Office activation/folder grants are deployment setup.
Downloads does not guarantee prompt-free access. The Office recipe requires
Microsoft Office on macOS or Windows; it does not automate LibreOffice on Linux.
Existing host integrations should review the authorization and continuation
behavior in [the strategy guide](../STRATEGY.md).

## Verification and limits

The release suite contains 371 tests. Local validation covers the full suite,
the native read-only smoke command, documentation links and packed contents
(including the showcase image). The repository CI repeats native builds and
tests across its platform matrix before release.

A live Astra studio run exported 105 trusted pointer strokes across seven colors
in 15 model calls. The README image is the original 103,717-byte PNG recovered
from the recorded tool result; it is not a recreation. Deterministic macOS Office
smoke tests previously verified saved Word, Excel and PowerPoint contents.

The run console was verified live on macOS across two turns of one conversation,
driven from a browser by an ADK-Rust agent on DeepSeek Flash: a plan declared, task
states advancing with measured notes, real Blender frames captured through the
session, and a follow-up message picked up as a second turn with a clean plan. The
scripted host walkthrough was verified separately with no API key, and both packaged
binaries were verified by installing the packed tarball into a clean directory and
running them through `node_modules/.bin`. `mouse_drag` was verified against a live
Blender viewport on macOS.

A complete model-driven Office run, Windows COM execution, native installed paint
apps, shipping MCP App hosts and comparative task benchmarks remain unverified.
`mouse_drag` is implemented for all three platforms but has only been exercised at
runtime on macOS. The console's browser bridge has been exercised in Chromium only.
These limitations are not claims of failed or absent core MCP functionality.
No superiority over another computer-use product is claimed.

## Release checklist

1. Align root/platform manifests and protocol identities at 7.2.0.
2. Run the full tests and verify the packed runtime, skills, docs and demo image.
3. Push the release commit and run the native CI matrix through a pull request.
4. Merge the validated changes, tag the release commit as `v7.2.0`, and publish
   the GitHub release.
5. The main-branch workflow builds a universal tarball, records provenance/SBOM
   evidence, and submits npm staged publishing. A maintainer must approve that
   staged package under the registry's policy. GitHub publication alone does not
   mean npm publication has completed.

Upgrade once npm staging has been approved:

```sh
npm install @zavora-ai/computer-use-mcp@7.2.0
```
