# v7.6.0 — the design pass: a smaller, honest, platform-true tool surface

Released 2026-10-09. Includes everything built as 7.5.0 on 2026-10-01 ([its notes](https://github.com/zavora-ai/computer-use-mcp/blob/v7.6.0/docs/releases/v7.5.0.md)), which was never
published on its own. Review and measurements: [the review](https://github.com/zavora-ai/computer-use-mcp/blob/v7.6.0/docs/reviews/2026-10-09-desktop-control-review.md) and
[the design second pass](https://github.com/zavora-ai/computer-use-mcp/blob/v7.6.0/docs/reviews/2026-10-09-design-second-pass.md); the change was [PR #37](https://github.com/zavora-ai/computer-use-mcp/pull/37).

## Why

Measured on the live server before the change: the default `tools/list` was 73 tools and 112,727 bytes (about 30k
tokens) in every host that loads the list; half of the schema bytes were the same seven targeting parameters repeated on
every input tool; five of the twelve largest tools were click variants that differ by one enum value; `approval_token`
was advertised on 40 schemas; every tool carried seven `_meta` fields; and the server's instructions still told every
host to prefer the accessibility tree, which is empty on Unreal, Blender and games. Discovery had been optimised in 7.2
(a host-side search library and permission tiers); the surface the model sees had not.

## What an agent sees now

| | Tools | Bytes on the wire | About |
|---|---:|---:|---|
| Default (`desktop`) | 39 | 45,942 | 12k tokens |
| `full` on macOS | 76 | 84,037 | 22k tokens (was 112,727) |

- **Default profile `desktop`**: observation, coordinates, OCR for apps that draw their own UI, the waits and the session
  target. `COMPUTER_USE_PROFILE=full` lists everything; `core`, `ax`, `scripting` and `windows-admin` still bound the
  surface. Profiles nest: core ⊆ desktop ⊆ ax, scripting, windows-admin ⊆ full.
- **Platform-true**: a tool that does not exist on your platform is neither listed nor callable (`registry` and
  `notification` are Windows-only; the OCR tools and waits are macOS-only; Spaces are macOS and Windows). Every tool has a
  `job` (observe, act, semantic, script, admin, browser, spaces, meta) in the catalog.
- **One `click`** with `button: left | right | middle` and `count: 1 | 2 | 3`, the usual targeting and `delivery`.
  `left_click`, `right_click`, `middle_click`, `double_click` and `triple_click` remain callable as thin aliases and still
  accept `target_app`, `target_window_id`, `delivery` and `force`.
- **Shared parameters** (`target_app`, `target_window_id`, `target_title`, `focus_strategy`, `force`, `delivery`) are one
  sentence each; the guidance moved to the instructions and `get_tool_guide`.
- **Instructions are generated for your platform and profile** from the catalog, and describe this release: the route
  order with OCR for self-drawn apps, the user-active guard and `delivery`, the waits, the session target.
- **`approval_token` is not in any schema.** Pass it in the call's `_meta["computer-use/approval_token"]`; it is also
  still accepted as an undeclared argument. Policy behaviour is unchanged.
- **Two `_meta` fields per tool** (`computer-use/focusRequired`, `computer-use/mutates`); `get_tool_metadata` still
  returns the full set.

## New

- **`set_target {app | window_id | title | clear}` and `get_target`**: the session target made explicit. Input and
  capture tools can omit targeting once one is set; `get_target` shows the app, window, title and whether it is on screen.
- **`wait_for_text`** (macOS): wait until text appears in a window, or disappears with `gone: true`, by on-device OCR.
  Returns the matched line with its box in window points and its screen point.
- **`wait_for_stable`** (macOS): wait until a window has stopped changing, meaning two consecutive captures identical for
  `quiet_ms`. `quiet_ms: 0` returns the first capture and its hash. `region` is accepted and reported as `regionApplied:
  false` until the capture helper gains a crop.
- **`screenshot full_screen: true`** captures the whole screen even when a session target is set.
- `read_window_text` returns each line's `box` in window points plus the window's `screen_origin` once (screen point =
  origin + box); the per-line `screen` rectangle is gone. `get_app_capabilities` reports `accessibility: { nodes,
  hasControls }` and `accessible` now means the tree has controls, not merely a window.

## Fixed

- **macOS permission failures are named and refused rather than silent**, contributed by
  [@swiftkimani](https://github.com/swiftkimani) ([#34](https://github.com/zavora-ai/computer-use-mcp/pull/34)). macOS
  discards synthesized input from a process that is not trusted for Accessibility and reports nothing, so clicks, typing,
  keys, scrolls and drags used to return success while nothing happened. Every input entry point now refuses with
  `accessibility_permission_denied` and names the setting to enable; `doctor` asks TCC for the real Accessibility and
  Screen Recording grants instead of inferring them; a failed `screencapture` says `screen_recording_permission_denied`
  or carries its exit status and stderr, and its child no longer inherits the server's stdio; `run_script` names
  Automation when an Apple event is refused; the pointer overlay is anchored to the primary display. In 7.6.0 the same
  check covers the paths added since the fix was written: `delivery: "pid"` clicks, scrolls, keys and text, and
  `type mode: "keys"`. The host that owns these permissions is the app that launches the server (your terminal, Cursor
  or Claude Desktop), not `node`; AGENTS.md has a Cursor section saying so.
- **The user-active guard refused the first input call of every fresh server.** The passive input tap stamped "last
  physical input = now" when it installed. The clock is now seeded from the system's own idle counter, with a clock base
  that can represent input before the process started. This was PR #35's red macOS CI.
- **Two ScreenCaptureKit captures at once hung each other** (found live while testing the waits: fifteen sequential
  helper runs passed, two side by side both stalled until killed, and the wrapper reported the killed helper as a silent
  `exit 1`). Helper runs are now serialised within a server and across servers through an advisory lock in
  `~/Library/Caches/computer-use-mcp/helper.lock` (taken over from a dead process, waited for from a live one, then
  `helper_busy`); a helper killed by the timeout is reported as `helper_timeout`; and the Swift helper gives up on a
  stalled capture after 10 s with `sck_timeout`.
- `process_kill` refuses `pid` 0, 1 and negative values (POSIX `kill(-1)` signals every process) and matches names exactly;
  an ambiguous name is refused unless `all: true`.
- `hold_key` is capped at 10 s; the hold runs on the server thread, so an unbounded one froze every other tool.
- Start-up tolerates empty or non-numeric environment values, logs unhandled rejections instead of dying silently, and
  recognises the module's real path. **`dist/launch.js`** (now the package `bin`) checks `node_modules`, `dist` and the
  native module before loading the server and names the fix on stderr; the TypeScript build swaps `dist` in atomically.

## Upgrading

- If your agent relied on `run_script`, `filesystem`, `get_ui_tree`, the browser tools or `process_kill` being present by
  default, set `COMPUTER_USE_PROFILE=full` (or `ax`, `scripting`, `windows-admin`).
- Agents that pass `approval_token` as an argument keep working; prefer the call's `_meta`. Hosts that read the seven
  `computer-use/*` metadata fields set `COMPUTER_USE_FULL_WIRE_META=true`, or ask `get_tool_metadata`.
- Agents that called `left_click` and friends keep working; new prompts should use `click`.
- Start the server with the `computer-use-mcp` command (or `node dist/launch.js`) so a broken install is reported rather
  than seen as a closed connection.
- macOS: grant the host app Input Monitoring if you want the user-active guard to see your typing and mouse; without it
  the guard allows every call and `doctor` says the clock is unavailable.

## Known limits

- `wait_for_stable` hashes the whole window; `region` is reported but not applied until the helper crops.
- The OCR tools and waits are macOS 14+ (ScreenCaptureKit and Vision). Windows and Linux ship the same server with their
  own capture paths; this release was verified live on macOS and by CI on the other platforms.
- The per-platform native packages ([#36](https://github.com/zavora-ai/computer-use-mcp/issues/36)) are still
  manifests only; the universal tarball bundles every native target.
- The "honest actions" contract (`effect`, `route`, `delivery` on every result, capture-bound clicks) is specified in
  [`docs/specs/v7.6-honest-actions/`](https://github.com/zavora-ai/computer-use-mcp/blob/v7.6.0/docs/specs/v7.6-honest-actions/requirements.md) and is the next release.

- Unit tests: 528 (527 pass, 1 skipped) on five CI platforms; native tests 12; lint and typecheck clean.
- Budgets are tests on the real transport: [`test/v7.6-tool-surface.test.mjs`](https://github.com/zavora-ai/computer-use-mcp/blob/v7.6.0/test/v7.6-tool-surface.test.mjs) (`desktop` under 48,000 bytes, `full`

- Live on macOS: the launcher starts the server; two concurrent servers capture the same window in under five seconds;
  the guard's first reading tracks the system idle counter; `wait_for_text` found a menu label in one poll.
