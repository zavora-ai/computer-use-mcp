# v7.6.0: the design pass

What a model sees from this server is smaller, current and platform-true. Measured before the change on the live
server: the default list was 73 tools and 112,727 bytes (about 30k tokens), half of the schema bytes were the same seven
targeting parameters repeated on every input tool, five of the twelve largest tools were click variants, and the server
instructions still told every host to prefer the accessibility tree (empty on Unreal and Blender).

## What changed for an agent

- The default profile is **`desktop`**: core plus the OCR and wait tools. 39 tools on macOS, 45,942 bytes on the wire (about 12k tokens); `full` is 84,037, down from 112,727.
  `COMPUTER_USE_PROFILE=full` lists everything.
- **One `click`** with `button` and `count`; `left_click` and the other variants stay as thin aliases.
- **`set_target` / `get_target`**, **`wait_for_text`**, **`wait_for_stable`**, `screenshot full_screen`.
- Tools that don't exist on your platform are not listed. `approval_token` is passed in the call's `_meta`, not in the
  arguments. Two `_meta` fields per tool.
- Instructions are generated from the catalog for your platform and profile.

## What changed for an operator

- `COMPUTER_USE_PROFILE=full` to keep the old surface; `COMPUTER_USE_ADVERTISE_APPROVAL_TOKEN=true` and
  `COMPUTER_USE_FULL_WIRE_META=true` to restore the old schema and metadata shapes.
- Start the server with `dist/launch.js` (the package `bin`): it checks the install and names the fix on stderr.

## Fixes

Two ScreenCaptureKit captures at once used to hang each other (and were reported as a silent `exit 1`); capture-helper
runs are now serialised within and across servers, timeouts are named, and the helper gives up on a stalled capture after
10 s with `sck_timeout`. The user-active guard no longer refuses the first input call of a fresh server; `process_kill` can't broadcast a
signal; `hold_key` is capped at 10 s; start-up tolerates bad environment values and logs unhandled rejections. See the
CHANGELOG.
