# v7.4.0 — read the browser, watch the cost, stop the run

Every change here came from something failing while an agent was actually driven, not
from a design review. The most useful of them came from watching a model spend five
minutes and thirty tool calls failing to type a password into a login form.

## The headline: ask the page, do not estimate

Pixels are lossy in a way that is easy to underestimate. A capture arrives 1024 wide
for a 2560-wide screen, so each image pixel is 2.5 real ones, and a form field is about
35 logical pixels tall. An agent reading a field's position off that image and
multiplying missed by **15, 50 and 77 pixels** on three successive clicks — an error
that grows with distance, which is the signature of a wrong scale rather than a wrong
offset.

The page already knows exactly where its controls are.

```typescript
const found = JSON.parse(text(await client.callTool('browser_find', { selector: 'input[type=email]' })))
const field = found.matches[0]      // { x, y, rect, label, enabled, in_viewport }
await client.callTool('left_click', { coordinate: [field.x, field.y], target_window_id: winId })
await client.type('someone@example.com', undefined, { targetWindowId: winId })
```

**The DOM locates, the desktop tools act.** Signing into a dashboard this way took three
`browser_find` calls, three clicks and two types, first attempt. The same task by pixel
estimation took more than thirty calls and did not succeed.

### Why this is not a browser-automation server

For a fresh browser context, a Playwright MCP server is the better tool, and the
tool-priority list in [AGENTS.md](../../AGENTS.md) says so. What Playwright cannot reach
is the session the person is already signed into. That is what these three tools serve,
and it is the only reason they exist.

### Three tiers, probed per call

| Tier | Needs | Gives |
|---|---|---|
| `browser_tabs` | nothing on macOS | open tabs, titles and URLs |
| `browser_page_text` | opt-in, plus a JS transport | the front tab's readable text |
| `browser_find` | same | elements with click coordinates |

Chrome, Edge, Brave and Safari through AppleScript; any Chromium through a DevTools port
you opened. A tier that is unavailable says exactly which setting or variable would
enable it — the `-1723` a browser returns when Apple-event JavaScript is off is
detectable, so it is named rather than reported as "unavailable". An agent told the
setting can ask for it; one told "unavailable" starts guessing at pixels, which is the
expensive path.

## What a run costs, and how to stop it

Both of these exist because of failures in one working session: a model balance ran out
mid-run with nothing on screen to warn, and a turn spent five minutes going nowhere with
no way to stop it short of killing the process.

```
14 calls · 412k in / 9.4k out · 94% cached · 21k thinking · USD 0.1283
```

Reported by the host driving the run, because usage arrives with the model response and
nothing inside an MCP server sees it. **Money appears only when priced** — set
`COMPUTER_USE_PRICE_INPUT` and `COMPUTER_USE_PRICE_OUTPUT`. Token counts are a fact; a
rate hardcoded in the server would be wrong within a quarter, and a wrong cost is worse
than none. Reasoning is priced with output because that is how it bills, which matters:
one screenshot has cost 6,959 reasoning tokens.

Stopping is **cooperative**, and the naming says so. A browser page cannot recall a model
call in flight, so `run_cancel` records the ask and it appears in every run tool reply;
the agent sees it on its next call and stops cleanly, reporting what it has. A driver can
also watch it between stream events, which is faster and is what the bundled example
does. The button reads "Stopping…" rather than claiming the run has ended.

## The conversation survives a restart

`COMPUTER_USE_RUN_STORE` names a file. Unset keeps memory only — a console that quietly
started writing to disk would be a surprise.

The transcript is how a person steers a run mid-flight, so losing it to a restart loses
the conversation rather than a cache. Frames are deliberately excluded: a 300,000-byte
capture leaves a **472-byte** state file, and a reloaded run shows no frame until the
next capture, which is honest rather than stale.

## Verified

- **435 tests**, 0 failures; lint clean; native builds green on macOS, Windows and Linux
  across x64 and arm64.
- `browser_tabs` live with no configuration: **13 tabs across Chrome and Safari**, no
  unredacted token.
- `browser_find` live over CDP against Metabase: fields at `(622,501)`, `(622,604)`,
  `(622,704)`, and a full sign-in on the first attempt from those coordinates alone.
- Run state across a real host restart: same run id, transcript intact, host logging
  `resumed run`.
- Cost meter end to end: 184k in / 4.2k out / 173k cached / 6,959 reasoning →
  `USD 0.056207`.

Two bugs that only live testing would have found:

- **A token nested inside an encoded `redirect=` survived redaction.** A real tab carried
  `?redirect=%2Fd%3Faccess_token%3DSECRET`; checking only the outer parameter name let it
  through. Redaction is now recursive and depth-capped.
- **AppleScript's `tab` is shadowed.** Inside `tell application "Google Chrome"`, `tab`
  means the browser's tab *element*, so the script emitted the literal text `tab` between
  fields. A separator bound outside the block fixes it.

## Limits worth knowing

- **`browser_page_text` and `browser_find` are off by default.** A browser holds live
  sessions and its DOM can carry tokens, personal data and half-typed passwords, so this
  is closer to `run_script` than to `screenshot`. Credential-store hosts are refused as
  defense in depth, not as a boundary — a person can browse a credential store on any
  domain and the list cannot know.
- **`browser_tabs` needs no opt-in** and will report the person's open tabs. A window
  title is already visible to `list_windows`, but a URL is more, which is why
  secret-shaped query values are redacted unconditionally.
- **A window capture's scale is approximate**, because it includes the window's shadow.
  Use a screen capture when you need exact coordinates; the reply says which you got.
- **Cancellation is cooperative.** An agent that never calls a run tool and never checks
  will not stop. The bundled driver checks between stream events; yours should too.
- **A reloaded run has no frame.** By design.
- The five commercial browser paths beyond Chrome and Safari are exercised through CDP
  only; Edge and Brave share Chromium's behaviour but were not separately driven.
